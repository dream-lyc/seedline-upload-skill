# 恢复与错误说明

仅供 Agent 内部执行；对教师的回复遵循 [教师用语](communication.md)，不复制命令、字段或原始报错。

实际接口失败、连接中断或重启原批次时读取。操作状态来自账本和查询回执，不靠重新解析资料推断。

| 情况 | 对用户说明 | 执行动作 |
| --- | --- | --- |
| 等待发布确认／确认的版本已变 | 试题已检查或已修改，尚未发布，请查看最新预览并确认 | 不上传；重新校验和导出，等待用户明确确认后才调用confirm及run。 |
| 来源缺页／答案待核验／本地校验失败 | 本地待补或待修正，指出对象、位置和原因 | 修正候选资料；不提交草稿，不写服务端失败回执。 |
| 凭据过期、吊销、账号或 scope 不符 | 说明需要重新连接 | 按 onboarding.md 网站连接并核对 `/me`；同账号可继续原批次，不能更换其归属。 |
| 系统地址或管理员账号与账本不符 | 原批次绑定另一环境或账号 | 停止恢复，不把原媒体 ID 和键用于新环境。 |
| 明确接口错误 | 说明哪项录入未完成、可采取的动作和适用等待时间；隐藏内部错误码 | 保留该操作失败；用户选择重试后才执行，不自动循环。 |
| 超时、断网、响应不可解析 | 结果待确认，不能宣称回滚 | 使用原 operation＋幂等键查询；若已成功，采用原回执。 |
| 查询无记录 | 暂未查到，不代表另一在途请求不会提交 | 保留原键。用户选择重试时仍复用它，不能生成新键规避冲突。 |
| `submission_in_progress` | 原操作仍在执行或等待租约恢复 | 只读查询；由用户决定稍后重试，GET 不会启动执行。 |
| `idempotency_conflict` | 原键对应的请求事实发生了改变 | 保留原账本并核对历史结果；修改后的业务内容需要新操作，不能覆盖原事实。 |
| 媒体成功、内容失败 | 媒体已成功，内容未确认成功 | 复用原媒体映射、内容键和已冻结字节，不重复上传成功媒体。 |
| 内容成功、可选视频失败 | 题目已发布，视频单独失败或待确认 | 仅处理视频操作，不重新发布题目。 |

## 恢复步骤

1. 使用原账本路径和安全配置，通过 `/me` 核对环境及账号；固定原契约。
2. 查询所有结果未知的操作。本地工具 原子保存查询到的媒体 ID 和成功回执。
3. 媒体已成功而内容尚未冻结时，恢复原媒体映射，回填并完成最终本地校验，然后才冻结第一次内容请求。
4. 内容已经冻结时，重试复用原始 UTF-8 字节。修改 JSON 排序、字段或正文都不是相同请求；不能替换字节后沿用原键。
5. 等待用户选择要重试的操作。本地工具 生成新 nonce 和签名，保留原操作键及请求事实。

同一文件重新尝试使用原操作；用户更换文件、MIME、purpose 或 context 则属于新操作。对尚未发送或明确失败的媒体，可通过 `replace-media 原批次目录 原媒体占位UUID 新媒体.json` 保存新身份和操作，并保留旧操作历史。主体内容已经冻结时，仅允许更换后置解析视频；结果未知的媒体必须先查询，已成功媒体不能静默改绑。此流程不重新发布已成功题目。

题目／媒体请求不要把 `retryable=true`、429 或 `Retry-After` 解释为自动重试授权。网站连接只按其专用协议有限等待。已明确选择重试且仍持有同一版本发布确认时，可按原范围执行，无需再逐文件确认。旧批次缺少发布确认记录时，查询结果仍可恢复；任何新写请求必须先展示当前预览并取得用户明确确认，不能补造历史确认。

## 完成报告示例

“已发布 3 个题包和 1 份阅读卷，新增 4 个对象；2 个媒体已确认。1 个可选解析视频上传失败，题目发布成功不受影响。原批次保存在本机目录，视频可在你选择重试后继续。”

若根据历史回执恢复成功，说明“已确认原操作成功，本次新增 0 个”，不要把回执的原 `created_count` 再累计。诊断只报告安全字段；不展示完整请求签名、凭据文件或临时媒体 URL。

## 网站连接中断

先 `connect status`，有原连接则 `connect continue`。工具区分等待批准、候选已保存和已确认待验证；不要直接移动候选文件覆盖正式配置。已确认后网络故障只恢复身份检查；双会话提示已有连接时不另建第二份。取消／到期按实际状态结束；completed 不因原等待期限已过而被视为未完成。

清除本机连接信息与服务器吊销是不同操作。用户要求删除本机缓存时不要从旧聊天补回；网站上已完成的授权需由凭据管理正常吊销。
